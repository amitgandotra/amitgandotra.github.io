Big O: Time & Space Complexity

Every pattern in this roadmap gets judged the same way: how does its runtime and memory usage grow as the input grows? Big-O notation is the language for answering that. Get this down cold before the patterns — every "Time / Space" tag you'll see from here on assumes you can read and derive it yourself.

What Big-O actually measures

Big-O describes the upper bound on an algorithm's growth rate as input size (n) approaches infinity — not the exact runtime in seconds, and not the runtime on any one specific input. It answers: "if I double the input size, roughly how much more work does this do?"

Why constants and lower-order terms get dropped

An algorithm that does exactly 3n + 5 operations is still O(n). As n grows large, the 3 and the +5 become irrelevant next to the fact that work scales linearly with n — that shape is what Big-O captures. This is also why O(2n) and O(n) are considered the same complexity class, even though one is literally twice as slow in practice.

Ordered best to worst. Everything in this roadmap lives somewhere on this ladder.

How to analyze time complexity from code

  • Sequential statements: costs add, but only the dominant (largest) term survives — O(n) + O(1) simplifies to O(n).
  • Loops: multiply the cost of the loop body by the number of iterations.
  • Nested loops: multiply the cost of each level — two nested loops over n each give O(n²).
  • Shrinking loops: a loop that cuts the problem by a constant fraction each step (e.g. halving) is O(log n).
  • Recursion: complexity is (number of calls) × (work per call) — count how many times the call tree touches the input overall.

Space complexity

Space complexity measures auxiliary space — extra memory used beyond the input itself — as a function of n. Two details trip people up constantly:

  • The call stack counts as space. A recursive function that goes n calls deep keeps n stack frames alive simultaneously, even if each frame only stores a constant amount of data.
  • In-place means O(1) auxiliary space — you're modifying the input directly rather than allocating a new structure proportional to n.

Common mistakes
  • Confusing average-case with worst-case — hashmap operations are O(1) average but O(n) worst case under heavy collisions.
  • Forgetting the call stack — recursion depth directly translates to space, even with no explicit data structure allocated.
  • Missing a hidden cost inside a loop — calling sorted() inside a loop that runs n times turns an apparent O(n) into O(n² log n).
  • String concatenation in a loop can silently become O(n²) in languages where strings are immutable, since each concatenation copies the whole string so far.
